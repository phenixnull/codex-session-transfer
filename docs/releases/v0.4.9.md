# Codex Session Transfer v0.4.9

## Fixes

- Full provider Mirror now handles Codex paginated sessions whose current file is a reverted replacement rollout, such as `rollout-...-<thread-id>_<rollout-id>.jsonl`.
- History dependencies are resolved by the immutable rollout ID encoded at the end of the filename instead of the stable logical thread ID stored in SQLite and session metadata.
- Older physical rollout segments that are outside the current copy plan keep their original history pointer and byte offset, so a valid continuation is no longer rejected as a dependency cycle.
- Planned parent rollouts still run before their dependants; copied history pointers and byte offsets are rewritten to the destination rollout after the parent completes.
- Ordinary copies of replacement rollouts now produce a canonical destination filename whose stable thread ID matches the copied session metadata.
- Independent sessions continue to copy concurrently with live progress reporting.

## Verification

- 84 Python unit, transaction, HTTP-stream, concurrency, extended-path, sidecar-database, paginated-history, and rollback tests
- JavaScript workspace, UI contract, responsive Electron, runtime isolation, installer upgrade, window constraint, and release workflow checks
- Read-only preflight against the live `custom -> Fucheers` plan accepted all 2,570 source sessions and classified the one paginated continuation as an external physical-rollout dependency rather than a cycle
- Source semantics checked against the official Codex `rust-v0.148.0-alpha.15` rollout filename, lineage, and resume-provider implementation used by the affected desktop session
