# Codex Session Transfer v0.4.0

## Highlights

- Cross-machine imports can map selected sessions from any packaged project into custom Codex App working directories.
- Preserve-project mode keeps project names beneath a chosen target root.
- Single-workspace mode maps selected projects into one destination.
- Per-project overrides resolve name collisions and exceptional destinations.
- The desktop app includes a native target-directory picker; browser mode keeps typed-path support.
- Short desktop windows now scroll the main workbench, and narrow layouts use bounded, independently scrollable session lists.
- The Electron minimum window size is reduced to `720x480`.

## Import Safety

- Every target root and resolved project destination must already exist and be a directory.
- Preview detects preserve-mode destination collisions before any write.
- Imported rollout metadata keeps `session_id`, `id`, `cwd`, and `model_provider` aligned with the destination SQLite row and rollout path.
- `session_index.jsonl` remains limited to `id`, `thread_name`, and `updated_at`.
- Historical turn contexts, messages, command records, and tool output are left unchanged.
- Repository files and dependencies are not copied; only Codex session data is imported.
- Failed imports restore SQLite, session-index, and rollout-file state.

## Compatibility Evidence

The path and identity behavior was checked against the official `openai/codex` source at commit `5c19155cbd93bfa099016e7487259f61669823ff`, including exact `cwd` filtering in `thread/list`, rollout `SessionMeta`, SQLite thread metadata, and rollout-based database recovery behavior.

- Browser verification at `1366x768`, `1366x600`, `1280x720`, `1024x600`, and `700x800`
