# Codex Session Transfer v0.4.6

## Fixes

- Local `Mirror all` now treats the selected source provider as the canonical history and replaces the complete target provider without per-session matching.
- Source session IDs, rollout paths, titles, archive state, goals, memories, and other durable records are retained, so existing Codex sidebar entries resume through the target provider instead of an obsolete URL.
- Every persisted `session_meta`, `thread_settings_applied`, and `session_configured` provider setting is rewritten consistently with SQLite metadata.
- All affected runtime databases, source and target rollouts, and `session_index.jsonl` are backed up before target records are removed. Failed concurrent writes restore the original rollouts and roll back the database transaction.
- Rollout rewriting, backup, package import, and obsolete-target cleanup use bounded concurrency with streamed live progress.
- Copy no longer requires Preview or selected rows. Preview loads 24 sessions initially and fetches more only while scrolling.
- ChatGPT is now detected as a blocking writer alongside Codex and Codex++.

## Verification

- 77 Python unit, transaction, HTTP-stream, concurrency, sidecar-database, paginated-history, and rollback tests
- JavaScript workspace, UI contract, responsive Electron, window constraint, and release workflow checks
- Official Codex app-server documentation and `openai/codex` resume/provider persistence paths reviewed before implementation
